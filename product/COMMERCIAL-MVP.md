# Deutsch Daily 商业 MVP

更新日期：2026-08-24

## 结论

Deutsch Daily 已经证明了一个有价值的核心体验：真实视频、逐句对译、点词、生词本和 Anki 可以组合成一段顺畅的精读流程。它现在是一个质量不错的个人内容产品，但还不是可以收费的 SaaS。

最值得商业化的不是“每天两档 Tagesschau”，也不是“又一个双语字幕播放器”，而是：

> 把用户本来就想看的外语视频，变成一份可以逐句听懂、查词和复习的个人课程。

第一阶段不要同时做任意语言、任意网站、账户、支付、社区和完整 SRS。先验证一件事：用户是否会连续四周，把自己的德语视频带进来学习。

## 首批用户与任务

- 用户：中文母语、德语 B1–C1、正在备考/留学/工作的成年学习者。
- 高频场景：新闻、访谈、课程、播客视频，单条 3–30 分钟。
- 核心任务：在 15 分钟内听懂一段原本只能听懂一半的视频，并留下 3–10 个值得复习的词。
- 不服务：零基础系统课、少儿课程、口语陪练、影视资源聚合和视频下载。

## 双入口

### 入口 A：带一个视频来

统一深链格式：

```text
https://<product-domain>/open.html#<原视频 URL>
```

使用 URL fragment 而不是 path/query：原视频 URL 不会自动发送给静态托管服务器，也不需要用户手工编码 `://`、`?` 和 `&`。

MVP 的处理顺序：

1. 已收录的 Tagesschau 页面：直接跳到现成课程。
2. 明确许可的直链视频或用户自有视频：进入导入流程。
3. YouTube：只使用官方嵌入播放器；字幕来源未合规解决前，不承诺“一键生成课程”。
4. 其他网页：给出清楚的“不支持”状态、原因和可行替代，不假装正在处理。

“在链接前加一个前缀”适合作为传播口号；实际产品应同时提供粘贴框、Bookmarklet/分享菜单和浏览器扩展，降低手工拼 URL 的错误率。

### 入口 B：打开首页学习

首页继续提供两条编辑精选的德语新闻线，承担三个角色：

- 不注册就能体验完整学习页；
- 让用户形成每日使用习惯；
- 证明翻译和教学内容质量。

首页的第一主操作应是“粘贴视频链接”，精选栏目是第二入口。当前首页只像归档目录，新用户看不到产品还能处理自己的内容。

## MVP 范围

### 免费样板

- 每日两档德语新闻；
- 逐句德中对照、隐藏译文、句子跳播；
- 点词释义、本地生词本、文本/Anki 导出；
- 无账户，学习数据留在浏览器。

### 可收费能力

- 用户上传自己拥有权利的视频/音频，或导入明确允许处理的媒体；
- 自动转写、逐句对齐、翻译、词汇和语法提示；
- 生成私有学习页；
- 跨设备保存学习进度和生词；
- 删除原始媒体和派生数据。

### 明确不进首版

- “任意网站 100% 可用”；
- Netflix/流媒体抓取或绕过 DRM；
- 从 YouTube 非官方接口批量抓字幕或下载媒体；
- 任意语言教学质量承诺；
- 社区、排行榜、教师后台和完整课程体系。

## 商业模式

先采用免费精选 + 处理额度，而不是一开始做昂贵的全功能订阅：

- Free：精选课程、无限本地生词、每月少量试用处理分钟；
- Pro：按月包含一组视频处理分钟，超额购买分钟包；
- Creator（验证后）：教师/创作者把有权使用的视频发布为私有课程并分享给学生。

竞品公开价格大致落在每月 10–30 美元区间，但本产品早期的供给和品牌都更弱。定价测试宜从较低门槛开始，并用“处理分钟”约束 AI 成本；不要承诺无限转写。

## 成功指标

### 激活

新用户第一次会话内完成：视频成功打开 → 播放/跳播一句 → 隐藏一次译文 → 查一个词 → 保存一个词。

### 北极星

每周完成的有效学习会话数。一次有效会话至少包含 5 分钟页面停留，以及播放/跳句、查词或保存词中的两类行为。

### 早期门槛

- 30 名目标用户完成首次学习；
- 首周激活率 ≥ 40%；
- 第 4 周仍有 ≥ 20% 用户每周完成 2 次学习；
- 至少 10 人主动导入自己的第二个视频；
- 在没有“终身会员”折扣的情况下出现首批真实付费。

若用户只消费首页免费新闻、很少导入第二个视频，就说明内容本身有价值，但“把任意视频变课程”还没有形成付费需求。

## 推广顺序

1. 先在德语留学、备考和精听社群招 30 名封闭测试用户。
2. 用每日新闻做稳定内容钩子，每次只推广一个明确动作：“点开今天一条，盲听第一段”。
3. 访谈用户导入失败的真实链接，按出现频率决定下一个 provider，而不是按技术兴趣扩站点。
4. 用邀请码开放付费测试；在留存验证前不买大规模流量。

## 技术演进

### P0：静态产品壳（当前仓库）

- 首页链接输入；
- `open.html#URL` 深链解析；
- 已收录内容映射和诚实的支持/失败状态；
- 用户自带媒体、SRT/WebVTT 与可选逐句译文，在浏览器本地创建真实课程；
- 本地课程恢复、逐句跳播、隐藏译文、查词、生词本与 JSON 导入/导出；
- 本地保存最近打开的课程；
- 事件接口保持可替换，默认不做跨站追踪。

P0 现在可以验证“用户是否愿意把自己的第二个视频做成课程”，但本地媒体文件不会跨刷新保存，字幕课程也不会跨设备同步。自动转写、翻译、账户、额度和删除策略仍属于 P1/P2，不能把本地工坊宣传成云端自动处理。

### P1：合规导入服务

- 自有域名和商业托管，不再把 GitHub Pages 当 SaaS 主站；
- API、异步任务队列、对象存储和过期删除；
- 只处理用户上传、用户授权或许可证允许的内容；
- 转写/翻译任务按分钟计费并可重试；
- 数据导出和删除。

### P2：账户和收费

- 登录、跨设备生词/进度；
- 支付、额度、账单与退款；
- 隐私政策、服务条款、版权投诉与内容删除流程；
- 监控导入成功率、处理耗时、单位分钟成本和留存。

### P3：更低摩擦入口

- 浏览器扩展或系统分享菜单；
- 在允许的站点直接“用 Deutsch Daily 打开”；
- 根据真实请求量扩展语言和内容来源。

## 法律与平台红线

这不是法律意见，但在收费前必须解决：

- GitHub 明确说明 Pages 不得作为免费托管来运行在线业务或商业 SaaS。Pages 可保留为开源项目/免费样板，商业主站应迁移。
- ARD Online 条款把播放器 embedding 限定为私人、非商业用途，并禁止对嵌入播放器的使用收费。当前 Tagesschau 样板不能直接成为付费权益；若要商业使用，需要书面许可或换成许可明确的内容。
- YouTube 必须使用官方播放器并保留来源、品牌和控制；不要覆盖播放器或通过非官方抓取承诺公共字幕。
- 用户上传和派生的字幕、翻译、词表都需要版权声明、删除机制、保存期限和投诉入口。

## 本轮交付边界

本轮把 P0 做成可推广、可验证的产品入口，同时保留现有日更流水线。不会假造尚不存在的云端处理、账户或付款能力。页面上出现的每个主要操作都必须能工作，或明确标记为支持范围/候补入口。
